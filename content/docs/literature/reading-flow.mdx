## 一、三遍阅读法（Three-Pass Method）

大多数人读论文的误区是从头到尾线性阅读。更高效的方式是**分层递进**——每一遍有明确目标，根据需要决定是否继续下一遍。

### 第一遍：鸟瞰（5-10 分钟）

**目标**：判断这篇论文是否值得继续读。

```
阅读顺序：
1. 标题 + 摘要 + 关键词
2. Introduction 最后 1-2 段（作者总结自己的贡献）
3. 所有章节标题（不读正文，只看结构）
4. 所有图表 + 图注（图表往往是论文精华的浓缩）
5. Conclusion
6. 扫一眼参考文献（有没有你认识的论文/作者）
```

**第一遍结束后你应该能回答**：
- [ ] 这篇论文属于什么类型？（新方法 / 系统实现 / 实验分析 / 综述）
- [ ] 论文的核心贡献是什么？（1-2 句话）
- [ ] 和我的需求相关吗？

**决策**：不相关 → 停止；部分相关 → 存入「待读」；高度相关 → 进入第二遍。

---

### 第二遍：理解框架（30-60 分钟）

**目标**：理解论文的整体逻辑和方法框架，但不纠结细节。

```
阅读顺序：
1. Introduction 全文
   → 理解：问题是什么、为什么重要、已有方法的不足
2. Method / Approach
   → 理解：作者怎么做的（看框架图，跳过公式推导）
3. Experiments / Results
   → 理解：实验设计、对比基线、关键数字
4. Discussion / Analysis
   → 理解：作者怎么解释结果、有什么局限
5. 跳过：详细推导、补充材料、附录
```

**阅读技巧**：
- 在 PDF 上做标注（Zotero 内置阅读器或 PDF Expert）
- 黄色高亮 = 重要结论
- 蓝色高亮 = 方法描述
- 红色高亮 = 存疑 / 需验证
- 批注 = 写下自己的理解或问题

**第二遍结束后你应该能**：
- [ ] 用自己的话复述论文的方法（不看原文）
- [ ] 画出方法的简化流程图
- [ ] 说出 2-3 个关键实验结果的数字
- [ ] 指出论文的主要局限

**决策**：理解够用 → 写笔记，结束；需要复现/深入 → 进入第三遍。

---

### 第三遍：精读（1-3 小时）

**目标**：深入理解每个细节，达到「能向别人讲清楚」或「能复现」的程度。

```
阅读顺序：
1. Method 逐段精读
   → 理解每个公式的含义和推导
   → 理解每个设计选择的原因（为什么用这个 loss？为什么这样分层？）
2. 对照代码（如果有开源实现）
   → 代码和论文描述是否一致？
3. 实验部分逐表分析
   → 每个 ablation study 说明了什么？
   → 实验设置是否公平？
4. Related Work
   → 理解和其他方法的区别和联系
5. Supplementary Materials / Appendix
6. 标注所有不理解的地方 → 查参考文献或问 AI
```

**第三遍结束后你应该能**：
- [ ] 向同学讲清楚这篇论文（5-10 分钟）
- [ ] 指出论文的强假设和潜在问题
- [ ] 判断方法是否可以迁移到你的场景
- [ ] 如果有代码，能跑通并理解关键模块

## 二、AI 辅助阅读工作流

AI 可以加速阅读，但**不能替代理解**。正确用法是：自己先读 → 用 AI 解决卡点 → 自己验证理解。

### 推荐工具组合

| 工具 | 用途 | 配置 |
| --- | --- | --- |
| Zotero + Translate 插件 | 划词翻译难句 | 配置 DeepL 或 LLM API |
| Zotero + PapersGPT 插件 | 选中段落让 AI 解释 | 配置 Claude/GPT API Key |
| Cherry Studio / Claude 网页版 | 喂入全文深度问答 | 选择 1M 上下文模型 |
| NotebookLM (Google) | 上传 PDF 精确问答 | 免费，不编造外部信息 |
| Semantic Scholar TL;DR | 一句话判断论文是否相关 | 免费，搜索时自动显示 |

### AI 辅助阅读的正确流程

```
第一遍（自己读）：
  → 自己读标题、摘要、图表、结论
  → 形成初步判断

遇到卡点时用 AI：
  → "解释这个公式的物理含义：[粘贴公式]"
  → "这段方法描述中，X 和 Y 的关系是什么？"
  → "这篇论文的方法和 [某方法] 相比，核心区别是什么？"

第二遍结束后用 AI 验证理解：
  → "我理解这篇论文的方法是 [你的描述]，这个理解对吗？"
  → "这篇论文的 3 个主要贡献是什么？"（对照自己的总结）

精读时用 AI 辅助：
  → "这个 loss function 为什么要加 λ 这个超参数？"
  → "Table 3 中 method A 比 method B 好 2%，这个提升显著吗？"
```

### AI 辅助阅读的错误用法

```
× 不读论文，直接让 AI 总结 → 你什么都没学到
× 让 AI 写阅读笔记然后直接交 → 学术不端
× 完全相信 AI 对论文的解读 → AI 可能误解论文
× 用 AI 总结替代自己的思考 → 无法在组会上回答问题
```

## 三、一页式论文阅读笔记模板

每读完一篇论文，用以下模板记录。**不需要写很长**，每项 1-3 句话。关键是用自己的话写，而不是复制原文。

### Markdown 模板

```markdown
# [论文标题]

## 基本信息
- 作者：
- 年份 / Venue：
- 引用次数：
- 链接：[DOI 或 arXiv]
- 代码：[GitHub 链接，如有]

## 一句话总结
（用一句话概括：这篇论文做了什么、解决了什么问题）

## 研究问题
- 要解决的问题：
- 为什么重要：
- 已有方法的不足（gap）：

## 核心方法
（用 2-5 句话描述方法，可以画简图）
- 关键思路：
- 技术路线：
- 核心假设：

## 实验与结果
- 数据集：
- 对比基线：
- 关键结果：（列出 1-3 个最重要的数字）
- Ablation：（哪个组件贡献最大）

## 评价
- 优点：
- 局限：
- 和我的工作的关系：
- 可借鉴之处：

## 遗留问题
- 没看懂的地方：
- 需要追读的参考文献：

## 关键图表
（截图或描述论文中最重要的 1-2 张图）
```

### 填写示例

```markdown
# Attention Is All You Need

## 基本信息
- 作者：Vaswani et al. (Google Brain)
- 年份 / Venue：2017 / NeurIPS
- 引用次数：130,000+
- 链接：arXiv:1706.03762
- 代码：官方无，但 HuggingFace Transformers 有标准实现

## 一句话总结
提出 Transformer 架构，完全基于 self-attention 机制，
抛弃了 RNN/CNN，在机器翻译任务上达到 SOTA。

## 研究问题
- 要解决的问题：序列到序列建模中 RNN 无法并行化的瓶颈
- 为什么重要：训练速度限制了模型规模的扩展
- 已有方法的不足：RNN 顺序计算，无法利用 GPU 并行；CNN 感受野有限

## 核心方法
- 关键思路：用 multi-head self-attention 替代循环结构
- 技术路线：Encoder-Decoder + Positional Encoding + Multi-Head Attention
- 核心假设：attention 机制足以捕获序列中的长距离依赖

## 实验与结果
- 数据集：WMT 2014 EN-DE, EN-FR
- 对比基线：GNMT, ConvS2S
- 关键结果：EN-DE BLEU 28.4（超过之前最好 2.0），训练时间减少到 3.5 天
- Ablation：multi-head 比 single-head 好；head 数量 8 最优

## 评价
- 优点：并行化训练、可扩展性强、成为后续所有 LLM 的基础
- 局限：self-attention O(n²) 复杂度，长序列计算量大
- 和我的工作的关系：理解 LLM 基础架构的必读论文
- 可借鉴之处：attention 机制的设计思路

## 遗留问题
- positional encoding 为什么用 sin/cos 而不是学习的？
- 需要追读：BERT, GPT 系列
```

## 四、不同场景的阅读策略

| 场景 | 读多少篇 | 读到什么程度 | 重点关注 |
| --- | --- | --- | --- |
| **了解新方向** | 1-2 篇综述 + 5-10 篇代表作 | 第一遍 + 第二遍 | 方向全貌、关键问题、主要方法流派 |
| **准备组会汇报** | 精读 1 篇 | 第三遍 | 方法细节、实验分析、能回答提问 |
| **课程论文/文献综述** | 泛读 15-20 篇 + 精读 3-5 篇 | 混合 | 各方法的对比、发展脉络 |
| **复现实验** | 精读 1 篇 + 看代码 | 第三遍 + 代码 | Method 细节、超参数、数据预处理 |
| **毕设选题** | 泛读 20-30 篇近 3 年论文 | 第一遍 + 部分第二遍 | Future Work、Limitation、未解决的问题 |
| **写论文的 Related Work** | 泛读 30-50 篇 | 第一遍为主 | 各方法的定位、分类、和自己工作的区别 |

## 五、阅读效率提升技巧

### 时间管理

```
建议：
- 每天固定 1-2 小时读论文（比如早上 9-11 点）
- 一周精读 1-2 篇 + 泛读 5-10 篇 是合理节奏
- 不要一次读太久（超过 2 小时效率急剧下降）
- 读不下去时换一篇，或者先做笔记整理已读内容
```

### 读不懂怎么办

| 卡点类型 | 解决方法 |
| --- | --- |
| 专业术语不懂 | 查 Wikipedia / 教科书 / 问 AI |
| 数学公式看不懂 | 找该方法的入门教程或博客文章 |
| 整体逻辑跟不上 | 先读该论文引用的前置工作 |
| 实验部分看不懂 | 对照代码理解（如果有开源） |
| 英文太难 | Zotero Translate 插件划词翻译；但关键术语要记英文 |

### 建立阅读习惯

```
入门阶段（前 1-2 个月）：
- 每周精读 1 篇，写完整笔记
- 选导师推荐的或高引经典论文
- 不要急，读懂比读多重要

进阶阶段（3-6 个月后）：
- 每周精读 1-2 篇 + 泛读 5-10 篇
- 开始追踪 arXiv / Google Scholar Alerts
- 建立自己的论文分类体系

熟练阶段（半年以上）：
- 第一遍 5 分钟就能判断论文价值
- 能快速定位论文的核心贡献和局限
- 开始写自己的论文时能熟练引用
```

## 七、常见问题

| 问题 | 建议 |
| --- | --- |
| 读不懂 | 正常。先查术语，再读前置论文，不要死磕 |
| 读得太慢 | 不要逐字翻译。先抓结构（第一遍），再补细节 |
| 读完就忘 | 用模板记录。哪怕只写一句话总结也比不写强 |
| 不知道读哪篇 | 参考 [论文筛选标准](./paper-filter.mdx) |
| 笔记写了不看 | 定期回顾（每周花 15 分钟翻看本周笔记） |
| 论文太多读不完 | 大部分论文只需要第一遍。精读是稀缺资源，留给最重要的 |
